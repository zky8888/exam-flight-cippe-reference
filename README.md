# exam-flight-cippe-reference

一个真实 AI 陪考项目的方法参考版。

原作者在 2026 年 8 月到 9 月备考 CIPP/E（IAPP 欧洲数据保护认证）时，在 Codex 里和 AI 一起搭了一套备考系统：规则、记录、脚本和可视化都存在一个文件夹里，边学边改。这个仓库是那个项目的公开整理版，**保留方法、结构和工具，去掉了题库、教材内容和个人学习记录**。

## 这个仓库适合谁

- 想用 Codex 或 Claude 给自己搭一个 AI 考试陪练的人；
- 想看看“AI 陪考”在一个真实项目里具体长什么样：规则怎么写、记录怎么设计、脚本怎么核对进度；
- 已经在用 Exam Flight 备考陪练技能，想更深入了解方法来源的人。

## 先读什么

1. **[方法论.md](方法论.md)**：整套方法的完整说明，用大白话写的。先读这一份。
2. **[12-CIPPE刷题训练核心协议.md](12-CIPPE刷题训练核心协议.md)**：最完整的一份执行协议，包括做题六步、理由审计、错因诊断、撤除帮助。
3. **[teacher_prep/2026-09-15/teaching-preferences.md](teacher_prep/2026-09-15/teaching-preferences.md)**：关系结构记忆和首次教学顺序是怎么来的。
4. 其他文件按需要查阅，见下面的文件说明。

## 怎么让 AI 参考这个仓库

把仓库下载到本地，在 Codex 或 Claude Code 里对 AI 说：

> 请参考这个仓库的方法和文件结构，帮我搭建一个适合我自己考试的 AI 陪练。先读 README.md 和 方法论.md。只借鉴流程、规则和记录的设计，不要使用其中任何 CIPP/E 的学习内容。我的考试是【具体考试和科目】。

如果你装了 Exam Flight 备考陪练技能，它里面有一份专门的“原项目阅读指南”，会告诉 AI 每个文件该借鉴什么、什么不能照搬，效果会更稳定。

### 记录结构示例

### 脚本

| 文件 | 作用 |
|---|---|
| `scripts/close_daily_study.py` | 每日收课验收：检查各类记录是否一致 |

### 记忆系统的迭代过程

- `iterations/v1-obsidian-wiki/.plan/`：Obsidian 知识网络从设计到瘦身的 16 个迭代阶段；
- `wiki/_meta/`：知识网络的数据模型和回写规则。

## 使用前请注意

1. **脚本不能直接运行。** 题库、教材和真实记录都已移除，脚本依赖的数据库和数据文件不在仓库里。它们是写法示例，换成你自己的材料和记录格式后可以改造使用。
2. **部分链接打不开。** 原文件里有些链接指向未公开的文件（题库映射、教材内容、个人记录等），这是正常的。
3. **新旧规则并存。** 这些文件是边学边改的，同一份文件里写在前面的规则，可能被后面带日期的修订替代。看日期，以最新的为准。
4. **很多设置是原作者个人的。** 英文题面加中英双语反馈、每批 10 题、每天 60 到 90 分钟、BoK 能力簇，都是针对 CIPP/E 和原作者情况的设置，换考试请重新约定。
5. **不包含学习内容。** 文件里出现的 GDPR 等例子只是为了说明方法，不能当作 CIPP/E 复习资料，也不保证与现行法律一致。

## 哪些内容没有公开

- 题库原题、选项、答案和逐题映射；
- 教材正文和按教材整理的笔记；
- 原作者的每日学习记录、逐题作答、错题和回测记录；
- 只服务于个人的配置。
